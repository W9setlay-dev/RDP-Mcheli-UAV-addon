# Implementation source matrix

This matrix records the source-of-truth classification for currently known mission-system requirements.

| Requirement | Source category | Actual API/class | Reason | Verification evidence |
| --- | --- | --- | --- | --- |
| mission intent | EXISTING_PROJECT_LOGIC | `MissionDefinition`, `MissionValidationResult`, `RdpUavNetwork` | Operator intent is validated request data, not persistent execution state or authority | `MissionDefinitionTest`, `MissionDefinitionValidationTest`, `NetworkClientServerContractTest`; live server request path still requires runtime evidence |
| vehicle entity access | MCHELI_NATIVE | `com.norwood.mcheli.aircraft.MCH_EntityAircraft` | UAV entity lifecycle and identity are owned by McHeliCE, not the addon | `MissionLifecycle.findAircraft(...)`, `MissionManager.ensureAuthorized(...)`, `WingManFlightAdapter` |
| vehicle lifecycle | MCHELI_NATIVE | `MCH_EntityAircraft` and native aircraft metadata | The addon validates but does not own the aircraft lifecycle | `MissionManager.ensureAuthorized(...)`, `UavEnergyHandler`, `WingManFlightAdapter` |
| mission assignment | EXISTING_PROJECT_LOGIC | `MissionManager`, `AircraftAssignmentRegistry`, `MissionQueue` | Server-side assignment and queue are coordination, not the mission state machine | `MissionManager.create(...)`, `ownsAssignment(...)`, queue contract tests |
| mission state machine and execution | EXISTING_PROJECT_LOGIC | `RDPMission`, `MissionState`, `MissionLifecycle` | `RDPMission` owns runtime state and guards transitions; `MissionLifecycle` dispatches and updates it | `RDPMission.transitionTo(...)`, `MissionState.canTransitionTo(...)`, mission lifecycle tests |
| movement route and setpoint | WINGMAN_ADAPTER | `WingManFlightAdapter`, `WingmanEntry`, `MissionNode` | The adapter submits route nodes; WingMan sequences them and publishes effective `autoTargetX/Y/Z`; that setpoint is not a movement write | `WingManFlightAdapter`, `MissionLifecycle`, `FlightGuidancePlannerTest`; physical route response requires live runtime |
| final movement write | CUSTOM_ADDON_LOGIC + MCHELI_NATIVE | `MissionMovementAuthority`, `AirframeController`, `NativeAircraftControlAdapter`, `MCH_EntityAircraft` | The lease authorizes one addon attitude/throttle writer; McHeliCE integrates motion and collision | `MissionMovementAuthorityTest`, `AirframeControllerTest`, `NativeControlMathTest`, transformer test; runtime ordering/trajectory unverified |
| fixed-wing control law | CUSTOM_ADDON_LOGIC | `FixedWingFlightController`, `UavVehicleProfile` | Uses course/ground-track, bank, speed, and vertical response; does not implement rotary hover/collective behavior. VTOL-enabled McHeli planes are not separately detected or transitioned by current selection logic. | `AirframeControllerTest.fixedWingUsesTrackCourseAndAltitudeFeedback`; McHeli plane/VTOL API signatures recorded in `docs/api-verification-notes.md`; per-airframe live calibration required |
| rotary-wing control law | CUSTOM_ADDON_LOGIC + MCHELI_NATIVE | `HelicopterFlightController`, `AirframeController`, `MCH_EntityHeli` | Uses horizontal velocity/position and collective response; native helicopter type can independently select it | `AirframeControllerTest.helicopterSeparatesHorizontalAttitudeAndCollective`, native-helicopter override test; hover response live-unverified |
| profile, capability, and operational role | EXISTING_PROJECT_LOGIC | `UavVehicleProfile`, `VehicleCapability`, `MissionType`, `SwarmRole`, `SwarmAssignmentManager` | Profile/capability describes vehicle support; mission type is intent; swarm role is current assignment | `VehicleCapabilityTest`, `SwarmAssignmentManagerTest`, swarm allocation tests; role assignment must not mutate profile |
| target discovery | CUSTOM_ADDON_LOGIC | `TargetResolver`, `TargetClassifier`, `EntityList` | The addon resolves world entities and classifies them using registry IDs and world data, not a native mission engine | `TargetResolver.find(...)`, `TargetClassifier` |
| target filtering | CUSTOM_ADDON_LOGIC | `TargetSelector`, `TargetSpec`, `TargetClassifier` | Filtering is done by namespace and registry-id rules in addon code | `TargetSelector.matchesNamespace(...)`, `TargetSpec` |
| authoritative target lock | EXISTING_PROJECT_LOGIC | `RDPMission.targetId`, `TargetLock`, `TargetAuthority`, `ServerAiTargetLockHandler` | Server mission owns exact target UUID; resolver/tracker provide observations, not alternate lock identity | `RDPMission` lock methods, network UUID contract, lifecycle target-loss tests; live continuity unverified |
| client camera/HUD observation | CLIENT_PRESENTATION + NETWORK_REQUEST | `ClientAimRayTracer`, `RdpUavNetwork`, `RdpUavTargetHud` | Client submits selected UUID/point and renders synchronized telemetry; server validates UUID, policy, range, and a conservative aircraft/target bounds sightline, not the remote camera's exact view | Packet UUID contract tests; server world ray and actual station camera alignment require live runtime |
| target attack definition | WINGMAN_ADAPTER | WingMan `MissionNode.Type.ATTACK` and `WingManFlightAdapter` | Attack definitions are passed to WingMan rather than simulated by the addon | `WingManFlightAdapter.dispatch(...)` / `SquareStrikePlan` |
| navigation objectives | WINGMAN_ADAPTER | `WingmanEntry`, mission nodes, target coordinates | The addon supplies objective coordinates while WingMan steers the craft | `MissionLifecycle.dispatch(...)`, `WingManFlightAdapter` |
| decision proposals | EXISTING_PROJECT_LOGIC | `AiTaskRequest`, `AiDecisionEngine`, `AiTaskingService` | Decision/tasking may propose bounded work but does not create or execute a mission by itself | `AiTaskingTest`, `MissionPlannerTest`; server mission creation remains separately validated |
| capability detection | CUSTOM_ADDON_LOGIC + MCHELI_NATIVE | `UavVehicleProfile`, `VehicleCapability`, `WingManFlightAdapter`, `MCH_EntityAircraft` | Addon policy maps configured profile and native airframe/weapon facts to supported tasks; assignment roles are not capability | `VehicleCapabilityTest`, `WingManFlightAdapter`, local JAR signatures; game support needs runtime validation |
| operator commands | CUSTOM_ADDON_LOGIC | `RdpUavCommand`, `RdpUavClientKeys` | Command logic is entirely server-side and custom to the addon | `RdpUavCommand`, `RdpUavNetwork` |
| HUD synchronization | CUSTOM_ADDON_LOGIC | `RdpUavTargetHud`, `RdpUavNetwork.syncTargetTelemetry(...)` | HUD is addon-rendered and synchronized through custom packets | `RdpUavTargetHud`, `RdpUavNetwork` |
| persistence | EXISTING_PROJECT_LOGIC | `RDPMissionWorldData`, `MissionNbtCodec`, `ReportNbtCodec` | The addon owns the world-scoped persistence contract for missions and reports | `RDPMissionWorldData`, `MissionNbtCodec` |
| diagnostics | CUSTOM_ADDON_LOGIC | `RdpUavDebug` | Verbose logging is custom addon instrumentation | `RdpUavDebug`, logger usage in lifecycle |
| swarm coordination | EXISTING_PROJECT_LOGIC | `SwarmManager`, `SwarmRecord`, `SwarmTaskAllocator`, `SwarmAssignmentManager`, `SwarmTargetRegistry` | Swarm owns membership, current operational roles, and shared projections; each member mission retains its own state and target lock | Swarm allocation/assignment/registry tests; live coordination and save/reload unverified |
| reusable external logic | MCHELI_NATIVE / WINGMAN_ADAPTER | McHeli classes and WingMan entries | The addon should not duplicate real flight or weapon logic | Project docs and adapter boundary |
| contact telemetry | MCHELI_NATIVE + CUSTOM_ADDON_LOGIC | `ContactTracker`, `ContactSnapshot`, native entity identity | UUID continuity, bounded velocity and lifecycle are addon state; flight remains native | `MissionLifecycle.reacquire(...)`, `RdpUavTargetHud` |
| payload authorization/release/outcome | EXISTING_PROJECT_LOGIC + WINGMAN_ADAPTER + MCHELI_NATIVE | `MissionLifecycle`, `GuidedWeaponAdapter`, `MissileGuidanceController`, native `MCH_WeaponSet` | Mission owns authorization/outcome state; addon adapter validates and invokes native release; McHeli/WingMan owns projectile motion and effect | `GuidedWeaponTest`, `GuidedMissileMissionLifecycleTest`, local JAR signatures; actual launch/impact/effect remains live-unverified |

## Unresolved classification items

- Direct hostile-structure model detection is not yet classified as a first-class mission type; it is still a point/entity target abstraction.
- Full dynamic mission doctrine for hostile bandits, military vehicles, and anomaly tracking remains conceptual and should be implemented under `EXISTING_PROJECT_LOGIC` once validated.
- `RdpUavMod.ServerTickHandler` currently calls addon native controls at
  `WorldTick START` with `EventPriority.HIGHEST`. This callback annotation
  alone does not establish ordering after every WingMan callback; guarded
  movement helpers and live runtime ordering are separate evidence.

## Audit gate statement

Every currently known major requirement has been assigned a provisional source classification. The remaining work is architectural refinement rather than a blind rewrite.
